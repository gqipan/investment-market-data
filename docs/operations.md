## 日常检查

先查看 [Actions](https://github.com/gqipan/investment-market-data/actions) 的具体工作流、commit、结论和日志，再确认是否产生正式 Release：

- `check`：push、PR、手动和每日北京时间 20:17；测试、隐私、目录、合成包与消费契约验证。合成 artifact 保留 2 天。
- `release candidate`：仅手动生成和验算合成候选，artifact 保留 7 天。
- `daily index release`：每日北京时间 21:40、23:40、次日 09:00；无未发布的闭市会话时正常结束，有缺失会话时采集并追加累计包。真实行情附件只由该独立流程或另行验收的发布操作分发。

本地命令见[开发维护](development.md)，发布步骤和读取见[每日累计发布](daily-release.md)。GitHub 定时触发可能延迟；消费端以正式版本和实际交易日判断新鲜度。

## 失败与恢复

| 现象 | 行为与处理 |
|---|---|
| 没有新 Release，但运行成功 | 核对闭市会话窗口；没有待补交易日属于正常 noop，不创建周末空版本 |
| 缺少基线 | 普通运行失败；确认确实是首次启动后才用 `bootstrap=true`，现有基线无需重建 |
| 上游延迟或已建立指数未到区间末日 | 拒绝推进；保留上一正式版，下次定时检查重试同一缺失区间 |
| 日历不可用、上一版哈希或正文损坏 | 失败，核查日志、固定版本与独立归档；不自动换源、补零或跳过验证 |
| 回补报告 partial | 查看每指数的类型、缺口与频率；`--allow-partial` 只改变退出码，发布仍需独立复验与末日门禁 |
| 同日期 tag 或残留草稿已存在 | 工作流拒绝覆盖；检查该版本和上传状态，确认原因后另行处理；反复重跑不会自动删除草稿 |
| 输出目录已存在 | 使用新目录，保留旧快照与恢复证据；不要覆盖或混入不同来源历史 |
| 需要修订旧历史 | 保留旧包与依据，另行准备新 revision；当前日程固定 r1，不能通过重跑完成 r2 |

草稿上传完整后才正式发布；失败不改上一正式版。已经正式发布的不可变包不原地替换。旧有效缓存的保留、原子切换和回退由消费端负责，本仓库不管理生产有效指针或业务数据库。

## 归档与恢复验算

Git clone 不包含 Release 附件。独立归档保存代码 commit、固定 tag、压缩包、SHA256SUMS、覆盖报告、累计清单及修订／撤回记录。定期从归档校验外层哈希、安全解包、材料化并执行 `verify-registry-cache`。单数据集格式另外使用 `verify-release`；两者不可混用。

`data/` 中旧回补、原始响应缓存和本地报告属于恢复证据，`dist/` 是候选与下载产物；它们被 Git 忽略，仍参与隐私内容扫描。本轮整理保留既有真实数据与发布附件，没有用私人应用文件补齐历史。

## 当前限制与后续验收

- 没有完整 12 指数 PE/PB/股息率日历史；不同方法与实际观测频率继续分开。
- catalog 中不支持或受限的来源仍拒绝相应用途，不能把部分来源获准理解成全部放行。
- 已验证正式基线和手动检查；连续多个实际新交易日的增量发布与延迟补缺，需要后续真实运行记录证明，不能用周末 noop 或合成测试代替。
- 当前工作流没有 revision 输入和自动草稿清理；需要修订时单独准备，保留审计记录。
- `fetch-*` 仅支持匿名公开的单数据集包，累计包按独立读取路径处理；私人 Release 认证不在当前下载器能力内。
- 私人应用的部署、持续影子对照、生产切换和业务导入由所属项目独立验收，本轮没有重新核查或修改消费端。
